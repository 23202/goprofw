# 01 · 容器格式

## 三个文件

| 文件 | 大小 | 内容 |
|---|---|---|
| `FWUPD.TXT` | 10 B | `CAMERA:1` |
| `CAMFWV.bin` | 64 B | `WFPG` + 产品字母 + `XX.XX.XX` + CRC32(DATA.bin) |
| `DATA.bin` | 257,600,064 B (0xF5AAA40) | `GPRO` 容器，6 个镜像 |

### CAMFWV.bin

```
+0x00  "WFPG"          4B  magic
+0x04  0x47 'G' / 0x45 'E'   产品码（A 包 G，B 包 E）
+0x10  "XX.XX.XX"      8B  版本占位
+0x24  u32 LE          crc32(DATA.bin)   ← 实测吻合，不是签名
```

CRC 校验示例：

| 包 | DATA.bin crc32 | CAMFWV 里的值 |
|---|---|---|
| A | `00f570a0` | `00f570a0` |
| B | `3847bb71` | `3847bb71` |

## 顶层结构

```
0x0000 0x200  容器头（GPRO 结构，见下）
0x0200        分区表：每项 16B = name[8] + flags u32 + size u32，紧跟 size 字节数据
```

### 分区表

| # | 表项 | flags | size | payload | magic | 内容 | 熵 |
|---|---|---|---|---|---|---|---|
| 1 | 0x000200 | 0x00000000 | 0x019800 (104,448) | 0x000210 | GPRO | ARM64 stage-1（~104 KB） | 6.28 |
| 2 | 0x019A10 | 0x00040001 | 0x6A51210 (111,481,360) | 0x019A20 | GPRO | **RTOS / ISP 固件（唯一加密区）** | **8.00** |
| 3 | 0x6A6AC30 | 0x00070002 | 0x93BA20 (9,681,440) | 0x6A6AC40 | GPRO | Linux 内核 Image | 6.19 |
| 4 | 0x73A6660 | 0x00080003 | 0x3F07010 (66,088,976) | 0x73A6670 | hsqs | squashfs 4.0 / LZ4 根文件系统 | 7.02 |
| 5 | 0xB2AD680 | 0x00090002 | 0x00005D20 (23,840) | 0xB2AD690 | GPRO | DTB（FDT） | 3.62 |
| 6 | 0xB2B33B0 | 0x000D0003 | 0x42F7680 (70,219,392) | 0xB2B33C0 | GPRS | 资源包（提示音/屏参/AI 模型 license） | 4.92 |

- 表项 name 全部是 `MILBEAUT`（SoC 平台名，不是分区名）
- flags 低 16 位是序号（1,2,3,2,3），高位像是类型/版本标记
- 6 号结束于 0xF5AAA40，正好等于文件长度

## GPRO 镜像头（0x200 字节）

```
+0x000  "GPRO"                       4B
+0x004  96 B 签名块                   每个镜像、每次构建都不同（P-384 尺寸，疑似 ECDSA）
+0x064  00 ...                       尾部补零
+0x0A0  00000000
+0x0A4  33 22 11 00 77 66 55 44 BB AA 99 88 FF EE DD CC   16B 密钥槽（所有镜像相同）
+0x0B4  01 00 00 00
+0x0B8  00 02 00 00                  = 512
+0x0BC  u32 LE                       长度/校验字段（p1=0x19080，p3=0x93B808，p5=0x5B08）
+0x0C0  01 00 00 00
+0x0C4  02 00 00 00
+0x0C8  16 B tag                      每次构建都不同
```

### 关于 tag 的实测

对 p3（两包 body 完全相同）试过 md5 / sha1 / sha256 / sha384 / sha512，对
`header[0:0x60]`、`header[0:0xc8]`、`header[0x64:0xc8]`、`header+body`、`body` 等多种组合求摘要，
**没有一个匹配 16 字节 tag**。结论：tag 不是简单内容摘要，更像 MAC 或签名分量；不能用它反推验签范围。

## 加密判定

| 分区 | 熵 | 可打印率 | 零字节率 | 结论 |
|---|---|---|---|---|
| p1 | 6.28 | 0.248 | 0.178 | 明文（ARM64 代码 + 数据） |
| **p2** | **8.000** | **0.371** | 0.004 | **AES 密文** |
| p3 | 6.19 | 0.229 | 0.176 | 明文（未压缩内核 Image） |
| p4 | 7.02 | 0.364 | 0.114 | LZ4 压缩的 squashfs |
| p5 | 3.62 | 0.288 | 0.560 | 明文 DTB |
| p6 | 4.92 | 0.215 | 0.428 | 结构化资源包 |

可打印率 0.371 = 95/256，是纯随机数据的理论值。**只有 p2 被加密。**
