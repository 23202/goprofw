# 04 · 两版固件逐字节对比

A = `DATA.bin`（`WFPGG`，crc `00f570a0`）
B = `DATA_1.bin`（`WFPGE`，crc `3847bb71`）

两文件大小完全相同：257,600,064 B。

## 总表

| 区域 | 起点 | 长度 | 差异 |
|---|---|---|---|
| 容器头 | 0x000000 | 512 | 112 B（96B 签名 + 16B tag） |
| p1 头 | 0x000210 | 512 | 112 B（同上） |
| p1 body | 0x000410 | 103,936 | **仅 64 B 不同**（0x19330–0x1936F） |
| p2 头 | 0x019A20 | 512 | 112 B |
| **p2 body** | **0x019C20** | **111,480,848** | **99.61% 不同**（436,042 B 相同 ≈ 随机重合率） |
| p3 头 | 0x06A6AC40 | 512 | 111 B |
| p3 body | 0x06A6AE40 | 9,680,928 | **完全相同** |
| p4 表项 | 0x073A6660 | 16 | **完全相同** |
| p4 body | 0x073A6670 | 66,088,976 | **完全相同**（含全部 5 份 settings.json） |
| p5 头 | 0x0B2AD690 | 512 | 112 B |
| p5 body | 0x0B2AD890 | 23,328 | **完全相同**（DTB） |
| p6 表项 | 0x0B2B33B0 | 16 | **完全相同** |
| p6 body | 0x0B2B33C0 | 70,219,392 | **完全相同** |

## 解读

1. **Linux 侧 100% 相同**：内核、rootfs、5 套机型配置、DTB、资源包，一个字节都不差。
   → 两台机器的界面/模式差异不可能来自配置，机型配置是两个包里都有的同一份。
2. **差异只在 p2（RTOS，111 MB）**，而且它是唯一加密的分区（熵 8.000）。
   → PRO 的能力（8K60 的上限）实现在 RTOS 里。
3. **每张镜像的 96B 签名和 16B tag 都变了，哪怕 body 完全一样**（p3 就是这种情况）。
   → 签名带随机数（ECDSA），不能用"内容相同则签名相同"反推签名范围。
4. **p1 body 只差 64 字节**（0x19330 起，一段签名），说明两包的 stage-1 是同一份代码。

## CAMFWV.bin

```
A: 57 46 50 47 47 00 ...  "WFPGG"  crc @0x24 = 0x00F570A0
B: 57 46 50 47 45 00 ...  "WFPGE"  crc @0x24 = 0x3847BB71
```

`crc32(DATA.bin)` 实测吻合两个值 → 这一层是**校验和，不是签名**，改完包重算即可。

## 混合包

`tools/build_hybrid.py`：保留 A 的 Linux 侧，把 p2（0x19A20–0x6A6AC30，111,481,360 B）整块换成 B 的，
p2 大小相同所以分区表不用动，再重算 CAMFWV 的 CRC。产物：

```
DATA_hybrid.bin   257,600,064 B   crc32 c8f287f7
CAMFWV_hybrid.bin 64 B            "WFPGG" + c8f287f7
```

预期：除容器头签名外，与 B 包逐字节一致（已验证）。
风险与验签分析见 [05-boot-chain.md](05-boot-chain.md)。
